# Lab 2：地址空间与内存映射

## 实验目标

本实验在 Sv39 分页机制上完成用户地址翻译、受权限保护的 `trace`、跨页写入的 `get_time`，以及匿名内存映射 `mmap/munmap`。

## 用户指针访问

进入第四章后，用户虚拟地址与内核可直接访问的物理地址不再相同。内核使用当前任务的页表 token 查找页表项，再依据页内偏移定位物理页中的字节。

访问时同时检查：

- 页表项有效；
- 页具有用户态 `U` 权限；
- 读取要求 `R`，写入要求 `W`。

`sys_get_time` 写回的 `TimeVal` 可能横跨两个页面。实现先逐字节验证整个目标范围，确认所有页面可写后再复制，避免只写入前半段便失败。`sys_trace` 的单字节读写使用相同的权限检查，因此无法借助 trace 访问内核地址或写只读页。

系统调用计数仍保存在每个任务的 TCB 中，并在统一分发入口递增。这样第三章 trace 的语义在地址空间隔离后保持不变。

## `mmap`

映射前检查起始地址页对齐、长度非零、地址加法不溢出、范围位于用户低地址空间，以及权限位只包含 R/W/X 且不全为零。

长度不必是页大小的整数倍，覆盖范围按结尾向上取整。映射前遍历所有目标虚页；只要其中一页已经有效，就整体返回 `-1`，不会留下部分映射。检查通过后为每一页分配物理页框，并根据 `prot` 建立带 `U` 位的页表项。

## `munmap`

取消映射同样要求起始地址页对齐和长度非零，并把结束地址向上取整。操作分两遍完成：第一遍确认整个范围都存在；第二遍才清除页表项并从对应 `MapArea` 释放页框。这样错误范围不会造成部分取消映射。

## 调试记录

模板初始评测为 `4/16`，计时、trace、mmap 与 munmap 均未实现。第一版实现后达到 `15/16`，只剩组合映射用例失败。原因是错误地要求 `mmap` 长度必须页对齐；测试要求非整页长度合法，并按页覆盖范围检查冲突。移除该限制、继续对结束地址向上取整后，组合映射与释放能够闭环。

## 验证

在 WSL2 Ubuntu 中执行官方检查器：

```text
make -C ci-user test CHAPTER=4
```

测试覆盖只读/只写/读写映射、非法权限、重叠区域、非整页长度、错误取消映射、用户与内核地址隔离、跨页时间结构写回，以及第三章功能回归。以检查器 `16/16` 且报告检查成功为完成标准。

## 实验总结

本实验的核心不只是建立页表项，而是保证内存操作的原子性和权限语义。映射或取消映射都先验证完整范围，再统一修改；用户指针也必须同时满足存在、用户可访问和读写权限。这些边界检查把普通功能从“样例可运行”提升为可预测的内核接口。
