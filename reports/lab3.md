# Lab 3：进程与 Stride 调度

## 实验目标

本实验在已有地址空间和任务切换机制上实现独立进程创建 `spawn`、进程优先级设置，以及按权重分配 CPU 时间的 Stride 调度，同时保持前面章节的时间、内存映射、`fork/exec/waitpid` 等功能可用。

## `spawn` 的实现

`spawn` 与 `fork + exec` 的结果相似，但实现路径不同。内核先从当前进程地址空间读取以零结尾的程序名，再从内嵌应用表中查找 ELF。找到后直接通过 ELF 创建一个全新的任务控制块和地址空间，而不是先复制父进程的全部页面。

新进程拥有独立 PID、内核栈、用户地址空间和 Trap 上下文；其父指针指向调用者，同时加入父进程的子进程表和调度器就绪队列。程序不存在时返回 `-1`，成功时返回子进程 PID。该设计避免了 `fork` 中不必要的整地址空间复制。

## Stride 调度

每个进程增加两个字段：

- `priority`：调度权重，初始值为 16，合法值不小于 2；
- `stride`：已经累计的虚拟运行步幅，初始值为 0。

调度器每次从就绪队列中选择 `stride` 最小的进程，并在选中后执行：

```text
stride += BIG_STRIDE / priority
```

优先级越高，每次增加的步幅越小，因而在相同时间内被选中的次数越多。实现仍使用顺序扫描，适合实验中的小型就绪队列。

`stride` 使用无符号整数并允许自然回绕。比较两个步幅时，先执行 `wrapping_sub`，再把差值解释为有符号数，从而在差值不超过半个整数空间的调度不变量下正确处理溢出，而不会在长期运行后突然颠倒顺序。

`set_priority` 对小于 2 的输入返回 `-1`，合法输入更新当前进程权重并原值返回。

## 调试与验证

模板基线只有 `2/15`。完成地址空间兼容、`spawn`、优先级和调度器后，官方检查器功能项达到 `15/15`。Stride 压力测试中，优先级为 5 到 10 的六个进程，其 `运行量 / 优先级` 保持在相近范围，说明 CPU 份额与权重基本成正比。

验证命令在 WSL2 Ubuntu 中执行：

```text
make -C ci-user test CHAPTER=5
```

检查范围包括 ch2 至 ch5 的回归用例、40 个子进程批量创建与回收、指定 PID 等待、非法优先级和 Stride 比例测试。

## 实验总结

本实验把任务调度从固定轮转提升为可表达权重的比例调度，也区分了“复制现有进程”的 `fork` 与“直接装载新程序”的 `spawn`。实现过程中最重要的边界是保持父子关系、地址空间所有权和就绪队列三者一致，并让步幅比较在整数溢出后仍满足调度顺序。
